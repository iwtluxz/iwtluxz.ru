# Кабинет iwtxz

В `index.html` находятся регистрация, вход и настройки личной страницы. У каждого аккаунта отдельный черновик и адрес `/u/логин`. Пароли хешируются с индивидуальной солью; сессия хранится в HttpOnly cookie. Файлы сохраняются на сервере, а не в localStorage браузера.

## Запуск на этом компьютере

Из папки проекта в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

Открой `http://127.0.0.1:4173`, выбери «Регистрация» и создай аккаунт. Скрипт использует установленный Node.js 20+ либо встроенный Node в VS Code. Оставляй терминал открытым, пока работаешь с кабинетом; Ctrl+C остановит сервер.

Если Node.js доступен в PATH, можно использовать `npm run dev`. Для другого порта: `powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -Port 4174`.

Обычное открытие `index.html` двойным щелчком и статический HTTP-сервер не запускают API входа. Публичные страницы и кабинет должны открываться с одного сервера.

## Вход в существующий профиль iwtlu

Логины существующих страниц защищены от открытой регистрации. Для первоначального создания аккаунта владельца:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -SetupOwner
```

Введи `iwtlu` и придумай пароль длиной 8–128 символов. Затем в браузере выбери **Вход** и введи эти данные. Пароль не записывается скриптом в исходники или файл. После первого входа аккаунт хранится в локальном хранилище; следующие запуски сервера не требуют `-SetupOwner`.

Аналогично можно настроить владельцев `shakzy` и `strelokk`. Логин `strelok` — псевдоним `strelokk`. Заданные через окружение данные первоначального владельца не сбрасывают пароль уже созданного аккаунта. Пароль меняется в разделе «Аккаунт».

Для запуска обычным Node можно задать `BUILDER_OWNER_USERNAME` и `BUILDER_OWNER_PASSWORD` в окружении. Node.js 20.12+ также читает локальный `.env`; уже заданные переменные окружения имеют приоритет. Эти переменные предназначены только для первоначального создания соответствующего владельца; убери пароль из окружения или `.env` после этого.

## Что можно настроить

- Ник, заголовок вкладки, описание и надпись экрана входа.
- Аватар, его размер, фон картинкой/GIF или видео, затемнение, цвет акцента и шрифт.
- Музыку, название трека, обложку и повтор; в превью работают воспроизведение, пауза, перемотка и громкость.
- Discord, Telegram, Steam и видимость карточки Discord.
- Пароль аккаунта.

Файлы можно загружать с компьютера. Изображения: PNG/JPG/GIF/WebP, фон также MP4/WebM; музыка: MP3/OGG/WAV/M4A/WebM. Максимум **4 МиБ на файл**. Более крупный файл можно сжать либо указать прямую HTTPS-ссылку в соответствующем разделе. Сервер проверяет тип и сигнатуру загрузки. Ограничение выбрано с учётом [лимита бинарных запросов Netlify Functions](https://docs.netlify.com/build/functions/configuration/).

«Сохранить черновик» сохраняет настройки только для владельца. «Применить к странице» сохраняет и делает снимок настроек доступным по `/u/логин`. Следующие изменения черновика не меняют опубликованную версию до повторного применения. Для существующих профилей также подхватываются опубликованные настройки на их прежних страницах.

Применение настроек не пишет в GitHub и не заменяет исходные HTML-файлы. В этой работе ничего не загружалось и не развёртывалось на внешнем хостинге.

## Хранение и будущий хостинг

Локальные аккаунты, хеши паролей, черновики, опубликованные настройки и файлы находятся в `.local-data/`. Каталог исключён из Git и недоступен через локальный HTTP-сервер. Не удаляй его, если нужны аккаунты и настройки; для переноса на другой компьютер потребуется отдельный перенос данных. Для изолированных тестов можно задать `BUILDER_LOCAL_DATA_DIR` вне проекта.

На Netlify используются [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) и существующие Functions. Локальные аккаунты автоматически туда не переносятся. При будущем развёртывании аккаунт владельца можно первоначально создать через `BUILDER_OWNER_USERNAME` / `BUILDER_OWNER_PASSWORD` в настройках окружения Netlify, затем убрать пароль из окружения. Новые пользователи регистрируются сами. `BUILDER_LOCAL_DATA_DIR` на хостинге задавать не нужно.

`npm run build` собирает в `dist/` только публичные HTML/CSS/JS и ресурсы. `.local-data`, `.env`, исходники Functions и скрипты не попадают в статическую раздачу. `netlify.toml` настроен на этот каталог. GitHub Pages без отдельного сервера не поддерживает эту авторизацию и сохранение файлов.

## Проверка

```text
npm run test:builder
npm run build
```

Тесты используют временную директорию, реальный локальный HTTP API и не меняют пользовательские данные. Проверяются вход, регистрация, сессии, смена пароля, изоляция аккаунтов, загрузки, частичная выдача медиа, разделение черновика и публикации и выход.
